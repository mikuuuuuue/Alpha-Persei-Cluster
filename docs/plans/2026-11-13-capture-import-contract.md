# 抓包导入：当前能力与发布门禁

## 概览

导入器已能在临时目录构建、验证并原子发布新独立存档。真实 9 月 26 日样本仍阻塞：缺少 10 封普通邮箱明细，另有 144 个协议号没有经过首版状态映射审核。没有发布真实恢复档。

下一步是补齐同一登录会话的邮箱证据，并逐项审核未覆盖协议。不能通过删除源帧或复制供体载荷来消除缺项。

## 快速检查

从仓库根目录运行预览：

```powershell
python -B -X utf8 tools/import_capture_archive.py Alpha-Persei-Captures/2026-09-26_登录/rebuilt --name Capture-Preview
```

预览退出 `0` 表示报告已生成。报告中的 `missing_data`、`issues` 和 `ready` 决定证据是否齐全。

证据齐全后，才可增加 `--apply`。最终 UID 在普通建档锁内确定。指定 UID 已占用时拒绝；自动 UID 在锁内重新分配。存档名已存在时拒绝覆盖。

运行隔离自动检查：

```powershell
python -B -X utf8 tests/m3_import_check.py
```

### 普通邮箱

`30001` 证明总数和未读数均为 `0` 时，允许空邮箱。非空时，需要结束帧后同一连接的唯一 `30002/30003` 查询与应答。查询完成前不能有读信、领取、删除、收藏或摘要变化。

明细须与摘要数量、未读数一致，并提供可用正文或可解析的归档模板。导入器复用 `MailService` 的 `mail_archive/mail_templates.json`，只自动解析不含参数占位符的模板正文。报告保存这份归档的哈希；参数化模板、缺失模板和无效正文继续阻塞。标题不会用作正文替代。

9 月 26 日样本只有摘要，没有对应普通邮箱明细。另一份“商城邮件”样本不能证明属于同一快照，因此没有拼接使用。

## 构建与实际登录验证

构建只复制冻结白名单中的 34 张静态目录。不复制供体账号、供体 `login_push` 或 API 配置，也不额外注入默认赠品和预通资产。角色目录来自已打包的 `hero_blueprint.json`。

`build_imported_save()` 返回内存候选和初步报告。此时 `isolated_login=false`。发布入口在锁内用最终 UID 重建，再验证测试副本，验证成功后才创建暂存文件。

独立子进程使用正常的 `switch_active_database()` 和 `send_login_flood()`。默认存档、槽位、启动配置、动态版本文件和真实 SQLite 备份均指向临时目录。网络连接被禁止。待发布内存库前后 `iterdump` 必须一致。

验证会解码实际发送的字节，检查主人、15 个必需协议、协议顺序、唯一结束标记、资产值和原邮件明细／正文。正常登录在结束标记后还有既有好感推送，因此不把“结束标记是最后一个网络包”作为条件。

购买记录比较非零购买次数及每日货架。空商店的显示受活动拓扑影响，不能据此猜账号购买状态。所有捕获购买行仍写入目标表。

验证仅固定子进程的 `time.time()` 为捕获结束时间。其他日期接口和真实运行周期不由这项验证证明。普通登录可能在测试副本补发战令等邮件；新增邮件 ID 单独记录，原邮件必须保持。待发布候选不受补发或周期刷新影响。

## 原子发布与登记

普通建档和导入共用 `_creation_lock(SLOTS)`。锁内重读已用 UID，再构建最终候选。锁忙时保留原来的非阻塞行为，并明确返回忙碌错误。

暂存路径为 `SLOTS/.import-staging/<uuid>/<name>.db.stage`。文件关闭并验证后，用 `os.link()` 发布。文件名冲突或硬链接失败时，不覆盖现有文件。只清理本次成功创建的目录；链接和重解析点拒绝清理。

槽位同步、登记和删除共用跨进程锁。注册表写后复读失败时恢复原字节。无槽位或登记失败时，保留完整文件并报告“已导入、未分槽”；随后刷新区服列表可重新登记。
